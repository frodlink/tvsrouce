# 自建服务器（Cloudflare Worker）

> 这一步是**可选**的。不部署也能正常用工具，只是没有「固定地址 + 分类过滤」这两个能力。

## 为什么需要

| 需求 | 只有工具 | 工具 + 自建服务器 |
|---|---|---|
| 拿到一个能用的地址 | ✅ | ✅ |
| 地址永远不变，电视只填一次 | ❌ 每次给的都是公网源地址 | ✅ 自己的固定地址 |
| 隐藏敏感分类 | ❌ | ✅ |
| 兼容老安卓「分类空白」 | ❌ | ✅ |
| 抓 GitHub 上的直播列表 | ❌ 常被墙 | ✅ Worker 代理 |

## 需要什么

- 一个 Cloudflare 账号（免费注册）
- （可选）自己的域名；没有域名也能用 `xxx.workers.dev`

## 步骤 1：建 KV 命名空间

Cloudflare 控制台 → **Storage & Databases** → **KV** → **Create namespace**，名字随便，比如 `tvbox-config`。

创建完记下 **Namespace ID**（一串 32 位十六进制）。

## 步骤 2：建 Worker

控制台 → **Compute (Workers)** → **Create** → **Start with Hello World!** → 部署。

然后进 **Edit code**，把 `worker/worker.js` 的内容整个粘进去，覆盖原有代码，点 **Deploy**。

## 步骤 3：绑定

Worker → **Settings** → **Bindings**，加两个：

| 类型 | 变量名 | 值 |
|---|---|---|
| KV Namespace | `TVBOX` | 步骤 1 建的命名空间 |
| Secret（或 Text） | `UPLOAD_KEY` | 你自己编的一长串随机字符，比如 48 位十六进制 |

`UPLOAD_KEY` 建议用 **Secret** 类型：这是上传口令，泄露了别人就能改你的配置。
生成方法：`python -c "import secrets; print(secrets.token_hex(24))"`

## 步骤 4：自定义域名（可选但推荐）

Worker → **Settings** → **Domains & Routes** → **Add custom domain**，填一个你域名下的子域，
例如 `tv.example.com`。Cloudflare 会自动配好证书。

不用自定义域名也行，地址就是 `https://<worker名>.<账号>.workers.dev`。

## 步骤 5：上传初始内容

已经有工具的话，在工具里配好 `cloud.json` 点一次「检测全部」就会自动上传。

想手动传也可以：

```bash
# 配置（把 <你的域名> <key> 换掉）
curl -X POST "https://<你的域名>/upload?key=<key>" \
     -H "Content-Type: application/json" \
     --data-binary @custom_config.json

# 直播
curl -X POST "https://<你的域名>/upload-live?key=<key>" \
     -H "Content-Type: audio/x-mpegurl" \
     --data-binary @live.m3u

# 看状态
curl "https://<你的域名>/status"
```

上传成功后，电视端填：`http://<你的域名>/tvbox.json`

> 老安卓一定要用 `http://`；域名在 Cloudflare 上，http 和 https 都能访问。

## 步骤 6：让工具认识你的服务器

把 `examples/cloud.example.json` 复制成 `src/cloud.json`，填上自己的：

```json
{
  "config_url": "https://tv.example.com/tvbox.json",
  "upload_url": "https://tv.example.com/upload",
  "upload_key": "你的 UPLOAD_KEY",
  "status_url": "https://tv.example.com/status"
}
```

`account_id`、`zone_id`、`kv_namespace` 只有用脚本调 Cloudflare API 重新部署时才需要，日常不用。

## 步骤 7：验证

```bash
curl "https://tv.example.com/status"
```

返回 `{"ok":true,"sites":9,"live_channels":46,...}` 就成功了。

## 可选：分类改写

### 1. 规则结构

```json
{
  "rename": "学习",
  "sensitive": ["里番", "福利", "伦理", "理论", "三级", "无码", "有码", "情色", "成人"],
  "sites": {
    "bf": 73,
    "bdc": 55
  }
}
```

| 字段 | 说明 |
|---|---|
| `rename` | 保留下来的那个分类改叫什么 |
| `sensitive` | 命中任意一个就删掉 |
| `sites` | 每个站点要保留的 `type_id`（内容最多的那个） |

`sites` 里的 key 就是代理地址里的那段，`type_id` 需要自己去站点分类列表里挑：

```bash
# 看某个站点的分类和 type_id，挑内容最多的那个
curl "http://<源站>/api.php/provide/vod?ac=class"
```

### 2. 上传规则

```bash
curl -X POST "https://tv.example.com/upload-rules?key=<key>" \
     -H "Content-Type: application/json" \
     --data-binary @class_rules.json
```

改名单只要重传这一个规则，**不用改代码、不用重新部署**。

### 3. 把站点接口改成代理地址

```python
import base64
api = "https://源站/api.php/provide/vod"
b64 = base64.urlsafe_b64encode(api.encode()).decode().rstrip("=")
print("http://tv.example.com/site/bf/" + b64)
```

把配置里该站点的 `api` 字段换成这个地址。

> 为什么是路径而不是 `?url=`：老安卓的 TVBox 拼查询参数时会把已经有的 `?` 弄丢，
> 走路径就完全不会碰到这个问题。

## 接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/tvbox.json` | 配置（电视填这个） |
| GET | `/live.m3u` | 精选直播 m3u |
| GET | `/spider.jar` | 自定义 jar（如果传过） |
| GET | `/status` | 站点数 / 直播频道数 / 更新时间 |
| GET | `/rules` | 当前分类改写规则 |
| GET | `/site/<key>/<base64>` | 单站点接口代理 + 分类改写 |
| GET | `/proxy?url=<编码后的地址>` | 通用代理，用来抓 GitHub / jsDelivr |
| POST | `/upload?key=` | 上传配置 |
| POST | `/upload-live?key=` | 上传 m3u |
| POST | `/upload-jar?key=` | 上传 jar |
| POST | `/upload-rules?key=` | 更新分类改写规则 |

## 费用与配额

免费版每天 10 万次请求，个人看电视一天也就几十次，远远够用。
KV 免费额度每天 10 万次读、1000 次写，也够。

## 安全提示

- `UPLOAD_KEY` 当密码看待，不要写进公开仓库（仓库的 `.gitignore` 已经忽略了 `cloud.json`）
- `/proxy` 是通用代理，别在自己域名上给陌生人用，否则可能被拿去干别的
- `/upload*` 全部校验 `key`，`key` 不对直接 403
