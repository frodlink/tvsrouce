# 原理说明：它是怎么测的

## 一、配置源体检

1. **拉取**：并发请求 `sources.json` 里的十几个配置源（最多 40 个并发）
2. **宽松解析**：真实世界的 TVBox 配置脏得很，所以解析时做了这些兼容
   - BOM 头（`utf-8-sig`）
   - `//` 注释、对象/数组里的尾随逗号
   - JSON 前面带日志、后面带 HTML 的情况（截取第一个 `{` 到最后一个 `}` 再试）
   - 多仓配置 `{"urls": [...]}` 自动展开
   - `spider` 是 `;md5;xxx`、或者伪装成 `.jpg` / `.png` 的地址
   - 相对路径 `./x.jar` 自动补全成绝对地址
3. **站点体检**：对每个站点请求一次列表（`ac=class` 或 macCMS XML），4 秒超时
4. **判定**：能返回站点列表且站点数 ≥ 阈值的算「通过」，按响应延迟排序
5. **发布**：最快的那个作为「精选配置」，前 5 个塞进备选，站点上限 9 个

## 二、直播整理

这是最费时间的部分，分七步：

### 1. 收集

并发抓 6~8 个公开直播列表（默认 8 个，其中 2 个需要通过自己的 Worker 代理 GitHub），
结果本地缓存 6 小时，避免每次都把源站抓一遍。

### 2. 过滤

- 只留央视、卫视、体育，其余（地方台、港澳台、国外、广播）全丢
- 跳过纯电台（名字带 FM / 广播 / radio 的）
- 跳过已知会出问题的 CDN（有些 CDN 会给 1080p 但实际是纯音频流）

### 3. 目标

- CCTV-1 ~ CCTV-17 全要
- 卫视固定 24 个
- 体育台单独一组，只要快的

### 4. 测速

每条线路请求一次 m3u8 或 m3u，量首字节时间。超时的进「补测」队列，最后统一复测，最多 3 轮。

### 5. 码率估算

只靠播放列表判断不了码率，所以：

1. 取媒体列表里的最后一个 TS 分片
2. 只发 `Range: bytes=0-1` 的头请求，读 `Content-Range` 拿到分片总大小
3. 用分片时长反推码率

这样既准确又几乎不耗流量。

### 6. 编码与清晰度

只靠 URL 看不出编码，所以直接解析 TS 流：

- 先读 PAT，找到 PMT 的 PID
- 再读 PMT，看 `stream_type`

| stream_type | 编码 | 处理 |
|---|---|---|
| 0x1B | H.264 | 首选 |
| 0x24 | H.265 / HEVC | 可用，次于 H.264 |
| 0x1D / 0x42 | AVS / AVS+ | **排除**（很多盒子只有声音没有画面） |
| 0x0F | AAC | 纯音频，排除 |

清晰度方面：主播放列表里 `#EXT-X-STREAM-INF` 带 `RESOLUTION=` 和 `BANDWIDTH=` 就直接读；
没有的话解析 H.264 的 SPS 拿宽高。

### 7. 择优

| 分组 | 选择顺序 |
|---|---|
| 央视 | 1080p 且 ≤4.5Mbps → 720p 且 ≤3Mbps → 能用的里最低 |
| 卫视 | 1080p ≤4.5M → 1080p 4.5~11M → 540p 以上 ≤3M → 能用的里最低 |
| 体育 | 300ms 以内按延迟排，最多 6 个 |

输出顺序：央视按编号，卫视按（清晰度，名字）固定排序，体育按延迟。

## 三、合并与发布（需要自建服务器）

1. 把站点名加上序号（`1 旺仔|xxx`）
2. 配置的 `lives` 字段写成本地直播地址 `http://你的域名/live.m3u`
3. `POST /upload` 上传配置，`POST /upload-live` 上传 m3u
4. 上传后**回读校验**，确认云端内容和本地一致

这样电视端填配置地址一个就够了，直播会自动出现在「直播」里。

## 四、分类改写（可选）

老安卓上很多源会出现「分类空白」，原因是接口 URL 带了查询参数，老版本 TVBox 拼 URL 时出错。
解决办法是把接口改成**路径式**：

```
原来：  http://源站/api.php/provide/vod/?ac=class
改成：  http://你的域名/site/<key>/<原接口的base64>
```

Worker 收到请求后：

1. 把 base64 解回原接口地址
2. 拼上 TVBox 传来的查询参数，去源站取数据
3. **如果返回内容里带分类列表**（JSON 的 `"class"` 或 XML 的 `<class>`），就做一次改写：
   - 删掉 `type_name` 命中敏感词的分类
   - 保留规则里指定的那个（内容最多的），改名「学习」
   - 放到分类列表最后
4. 其他请求（列表、详情、搜索）原样透传

注意一个坑：**TVBox 取分类时不一定带 `ac=class`**，所以 Worker 是「看返回内容里有没有分类」，
而不是「看请求参数是不是 ac=class」。这一点踩了很久。

XML 站点也有坑：`<ty ...>名称</ty>` 的正则不能写成 `<ty[\s\S]*?</ty>`，
否则会从 `<type>` 标签一路匹配到别的地方，导致整个分类列表消失。
